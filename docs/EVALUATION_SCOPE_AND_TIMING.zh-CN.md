# System1Bench 测了什么，以及速度究竟测了什么

本文解释已有 v0.2 实测记录。本轮没有重跑模型；新增审查材料和文档均保留在本地，未上传 GitHub。[英文版](EVALUATION_SCOPE_AND_TIMING.en.md)。

## 模型与规模

实际测试了 **Laya English、Laya Multilingual、Llama-3.1-8B-Instruct、Qwen3-8B**，尚未测试 Jev。

每个模型覆盖 15 个数据来源、36 个套件（28 个主任务套件＋8 个选项顺序对照），包括 22,934 次逻辑状态请求、26,450 次决策。四个模型共 105,800 次决策，推理失败为 0。重复接口、对齐翻译、同状态多问题和对照实验不应视为独立样本。

## 已测试的能力与可靠性

| 方面 | 任务或数据 | 已记录指标 |
|---|---|---|
| 基础语义分类 | AG News、Emotion、SST5 | 准确率／参考一致率；适用时计算 macro-F1 |
| 意图路由 | Banking77、MASSIVE、CLINC | 完整候选空间下的分类结果 |
| 根据材料做判断 | BoolQ、XNLI、Jev–Laya claims、TurtleBench | 二分类／多分类参考一致率，Turtle 标签合并敏感性 |
| 结构化工作流 | typed-decisions、JevBench、ReflexBench、Jev–Laya | 选择、布尔、等级判断；按任务与问题分层 |
| 安全策略判断 | Aegis2、prompt-injections、moderation、guard | 对来源安全／注入政策的符合率 |
| 范围外请求识别 | CLINC150/OOS | 范围内准确率，OOS precision、recall、F1、AUROC |
| 有序评分 | SST5 等 score 任务 | 众数／期望等级 MAE、相差不超过一级的比例 |
| 中英文一致性 | 对齐的 XNLI、MASSIVE | 分语言准确率、预测一致率、双语都正确比例 |
| 其他语言 | Jev–Laya multilingual | 七语言工单判断，样本不是平行翻译 |
| 长上下文检索 | Jev–Laya needle | 不同长度和事实位置的表现；按原始 needle 聚类 |
| 选项顺序稳定性 | Banking77、MASSIVE EN、JevBench、ReflexBench | 同序重复与真实倒序的答案一致率和准确率 |
| 概率诊断 | 有效概率输出 | Brier、ECE、高置信错误；不默认概率已经校准 |
| 输入完整性与失败 | 全部套件 | 候选／问题／状态截断、候选碰撞、失败数、共同完整输入子集 |
| 统计不确定性 | 各来源 | 按同状态、故事、needle、重复提示分组的 bootstrap 区间 |

已有编码审计显示 105,800 个决策输入均完整。这只能说明编码保留情况；模型是否利用了信息、输入是否足以决定参考答案，是另外的问题。[本地合理性审查](DATASET_VALIDITY_AUDIT.zh-CN.md)已发现部分参考标签和可判定性问题。全部成绩见[中文结果](RESULTS.zh-CN.md)／[英文结果](RESULTS.en.md)。

## 是否测了输出速度？

**测了批次预测耗时，可据此计算本次工作负载的吞吐量。** 计时流程是：先完成输入审计，GPU 同步，启动计时器，调用适配器 `predict`，再次 GPU 同步，然后记录耗时。实现见 [run.py](../system1bench/run.py) 的批次计时部分。

每个模型有 3,041 条批次计时记录，配置最多每批 8 个逻辑请求，设备为 NVIDIA A100 80GB PCIe。以下统计包含全部 36 个套件及对照，来自原始批次记录的重新汇总，**没有新增速度实验**。

| 模型 | 累计预测耗时（秒） | 逻辑请求／秒 | 决策／秒 |
|---|---:|---:|---:|
| Laya English | 223.31 | 102.70 | 118.44 |
| Laya Multilingual | 129.10 | 177.64 | 204.87 |
| Llama-3.1-8B-Instruct | 2251.28 | 10.19 | 11.75 |
| Qwen3-8B | 2375.43 | 9.65 | 11.13 |

计算方式：逻辑请求／秒＝22,934÷累计预测秒数；决策／秒＝26,450÷累计预测秒数。一个状态可能有多个问题，所以两个吞吐量不同。批次时间除以请求数只是摊销成本，**不能当作单个请求实际等待的响应延迟**。

[机器可读计时汇总](TIMING_FROM_EXISTING_RUNS.json)保留了未四舍五入的数值、计算口径、元数据哈希和限制。这次汇总核对了全部 144 个压缩结果文件的来源哈希，批次合计与元数据一致。

## 计时边界与限制

- 包含适配器预测调用内部的 CPU 工作，以及 GPU 工作完成前的同步等待；首批初始化效应也保留，没有按统一预热流程剔除。
- 不包含下载、模型加载、单独执行的输入审计和结果写盘。因此它也不是从启动到评测完成的总用时。
- LLM 在输入审计时提前分词并缓存，每个问题各做一次下一 token logits 前向；没有持续生成文本或推理链，Qwen 关闭 thinking。Laya 使用原生批次决策接口。这些适配路径不代表相同计算量。
- 机器还运行着其他任务；不同任务的输入长度、候选数、问题数也不同。因此不能把这张表当作独占设备下的稳定硬件速度排名或在线服务延迟。

## 还没有测试哪些速度指标？

| 指标 | 当前状态 |
|---|---|
| 文本生成 tokens/s | 未测；本轮选择有限答案，没有持续自回归生成文本 |
| 生成服务的首 token 延迟 TTFT | 未单独测；LLM 路径是下一 token logits 评分 |
| 受控 batch size=1 单请求延迟 | 未测；已有运行最多每批 8 个逻辑请求 |
| 端到端请求 p50／p95／p99 | 未测；批次计时不能冒充单请求服务延迟 |
| 独占 GPU 的稳态吞吐和并发扩展 | 未在隔离、受控条件下测量 |
| 冷启动和模型加载时间 | 未计入当前预测耗时 |

若后续要正式比较速度，应在空闲设备上固定预热、输入长度、候选数和分词计时边界，分别测 batch size=1／8，并重复多轮，报告单请求延迟和 decisions/s。只有引入真正文本生成时，才应报告对应 tokens/s。以上是后续方案，不是已经完成的实验。

此外，本轮没有验证交互式智能体成功率、动作后果、真实业务收益、每条标签的独立人工裁决或训练去污染。Llama/Qwen 采用固定直接决策基线，其分数不代表长推理或提示优化后的最佳能力。本地审查建议不会追溯改变已冻结的分数。
