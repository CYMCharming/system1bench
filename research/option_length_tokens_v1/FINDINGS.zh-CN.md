# 绝对长度和相对长短，分别告诉了我们什么？

可以分别统计，而且不能互相替代。这里复用 23 个模型的已有选择，
没有重新调用模型，也没有改动准确率或综合榜。

## 两个问题，两种数字

- **绝对长度**：选中的答案有多少参考 token？它比同题随机选一个答案，平均长或短多少 token？例如 −3 表示平均少 3 个 token。
- **相对长短**：它在这道题的选项里排长还是排短？−100 是最短，+100 是最长，并列取中间位置。它不管选项相差 1 个还是 100 个 token。

例如，10 / 11 / 12 token 和 10 / 100 / 1000 token 两道题，选最短的
相对分都是 −100；但它们的绝对长度差距完全不同。
因此不能只用“平均选中了多少 token”判断偏好，要与**同一道题**的机会基线比较。

## 同一批 207 道题，确实能看到不同信息

以下是主参考 Qwen3 tokenizer；默认只比较 CRUXEval 和 When2Call。
所有模型使用同一批有效题，且这些题的字符长度和 token 长度都能区分选项。
区间是按任务分层、按来源组重采样得到的 95% 探索性区间，未做多重检验校正。

| 模型 | 平均比同题随机选多几个 token | 相对 token 长度分 |
| --- | ---: | ---: |
| Jev | −3.91 [−6.82, −1.80] | −22.17 [−32.08, −11.61] |
| Qwen3-8B | +1.47 [−1.46, +3.64] | +13.96 [+3.80, +24.22] |
| NanoJev | −2.68 [−5.43, −0.60] | −8.17 [−17.87, +2.34] |

直白地说：

1. **Jev 在这批题上，两种统计都偏向较短选项。**但正确答案本来就比随机选项平均短 2.57 token，不能把全部短向差异归因于不良偏好。错误题上，Jev 相对错误选项基线仍短 3.63 token，区间 [−5.97, −1.13]；这也是相关性，不能证明是长度导致了错误。
2. **Qwen3-8B 较常站在“相对长”的一侧，但“平均多几个 token”的证据没那么明确。**相对分区间不跨 0，绝对差区间跨 0。这说明排序和长度差距回答不同问题，不是模型前后矛盾。不能凭两个区间的宽窄宣布某指标更优。
3. **NanoJev 则相反：绝对差表现出短向关联，但相对排位还不够明确。**不能简单说“多数模型都没有偏好”，也不能说所有 S1 或所有通用大模型都是一个方向。

## 还有一个需要修正直觉的发现：字符短，不一定 token 少

在完全相同的 207 题上，Qwen3-8B 的字符排位分是 −10.16，
token 排位分却是 +13.96；两者配对差为 +24.13，区间 [+17.01, +31.50]。
**这是长度定义变了，不是模型的选择变了。**代码、数字和自然语言的分词方式不同，
不能把此前字符统计中的“短”直接改名成“token 少”。

网站保留原字符结果，并提供同题字符/token 对照。主 token 结论还使用另一套
Llama 3.2 参考 tokenizer 作敏感性检查；两个参考同时有效的比较固定在共同 202 题，
不把样本变化混作分词器差异。参考 token 统一衡量文本，但不是各模型内部原生 token。

## 为什么还要检查极端值？

有道代码题的错误选项是 702 位数字。Qwen 参考分成 702 token，Llama 参考分成
234 token；逐 token 解码核对确认不是程序错误。这样的单题容易影响绝对均值。

我们没有删除或截短它，而是另外报告中位数，以及每次去掉一个来源组之后的均值范围。
主参考下，Intern-Decision-4B 的绝对均值差 +2.13 token，
去掉该极端题的来源组后变为 −0.12；所以不能据此声称它“普遍爱选长答案”。
Qwen3.5-4B 的均值方向也会因去掉某一个来源组而改变。

## 应该怎么读网页？

先看绝对差与相对分是否同向，再看区间、正确答案基线、任务差异和极端值敏感性。
分箱图比较“实际选中率 / 同题可选机会率”，不是把每个长度段都假设成同样常见。
答错模式只对照错误选项，且不同模型的错误题不是同一批。

这些结果能定位值得进一步实验的现象，**还不能证明把同一个意思写长，就会让模型更喜欢它**。
要证明这一点，需要另外构造语义不变、只改变长度的配对实验，并独立审核改写是否真的等价。
