## 试跑现象与下一步验证

同一批完整候选试跑还完成了 Kev-9B、Qwen3.5-9B 和 NanoJev，共 5 个模型、1,770 次请求。上表专门保留 4B 配对参照；全部指标及修订见 `results.json`。NanoJev 保留原始 FP32 存储权重，BF16 autocast 推理，不是量化权重。各模型仅在各自完成全部请求并通过独立复算后发布。

NanoJev 在 CLINC 的 200 条中有 187 条预测为同一标签；该任务准确率为 1%。全部候选输入长度为 51–98 token，没有超过原模型训练的 8,192 token 长度。另取两套任务各自首、中、尾 3 条，直接调用官方 `DecisionPredictor.predict`，六条完整概率向量与记录一致（最大差值均为 0）。[复算记录](nano_native_replay.json)及 `check_nano_native.py` 已保留。这只能验证这六条的适配一致性，不是全量重跑，也不能解释低分原因；不删除异常结果，不据此推断整个架构的能力。

- CLINC 的总体准确率与宏 F1 排序相反：Qwen 总体多答对 2 条，Kev 宏 F1 高 3.34 个百分点。不能说其中一个模型在所有意图上更好。
- Qwen 的域外请求召回为 48 / 50（96%），Kev 为 41 / 50（82%）；已知意图准确率则分别为 114 / 150（76%）、119 / 150（79.33%）。两种能力应分开报告。将已知请求误拒绝为 OOS 的数量为 14、12 条。
- BANKING 上不是完全不同的两群题在抬高分数：相同 154 条中，Kev 独答对 30 条，Qwen 独答对 6 条；双方都答对 95 条，都答错 23 条。差异仍需更大样本及更多模型复验。
- CLINC 试跑的 OOS 比例为 25%，高于完整测试的 18.18%。每个已知意图只有 1 条，BANKING 每类只有 2 条；宏 F1 与单类表现可能很不稳定，不报告未建立的泛化置信区间或普遍优越性结论。

完整官方测试与扩展模型试跑另行运行。Intern 当前原生接口在 151 个选项上拒绝输入（最多 62 个答案符号），StartLux 当前原生接口最多 26 个选项。这属于原生单请求能力范围，不记零分、不视作判断错误。若研究层级路由系统，必须另行冻结流程、报告多次调用与错误传播，不能冒充本次单请求成绩。

## 可复验性

`analyze.py` 不调用推理运行器的评分函数：核验每个模型的 DONE、原始预测、原始清单、原始脚本、完整候选、请求哈希、合法概率和参考绑定，然后独立计算准确率、宏 F1、类别计数、Brier 与 NLL。无失败请求被移出准确率分母。

两个模型运行时的 JSON 字节格式不同（Windows CRLF / Linux LF）。分别保留各自原始清单，而不是替换其哈希；两份冻结案例和每个推理请求经语义及确定性序列化核对一致。`run_original.py` 是两个历史运行共同绑定的原脚本，不作格式化。

`prediction_projection.json` 发布的是不含原始话语文本的参考标签、预测、概率和请求哈希。原始数据来源与许可见 [准备协议](../public_expansion_v1/README.zh-CN.md)。`results.json` 包含原始结果哈希、权重修订、适配器、概率口径和全部聚合指标。宏 F1 按完整类别集合等权；多分类 Brier 未除以类别数，范围 0–2。真值概率为零时 NLL 记为不可有限表示，同时另列 1e-15 下限截断的诊断值及零概率条数，不隐藏截断。

公开复算：`python -m research.public_intent_pilot_v1.verify`。私有原始结果复算：`python research/public_intent_pilot_v1/analyze.py --input .aris/public_expansion_review_20261007 --check-only`。原始预测与冻结请求位于 gpu29 的 `.aris/`，不在 Git 中发布。
