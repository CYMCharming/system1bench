# 选项长短与模型选择：这次能说明什么

[网页交互图](https://system1bench.vercel.app/?view=length) ·
[全部分数 CSV](scores.csv) · [完整协议](PROTOCOL.md) · [结果 JSON](results.json)

## 1. 不是“S1 爱长，LLM 爱短”这么简单

默认比较 23 个模型共同完成的 221 道代码／工具题，每题选项长度不全相同。
长度位置分为负表示更常选相对短的答案，为正表示更常选相对长的答案；
这不是准确率，绝不是越接近零越好。正确答案本身的分数为 **−5.46**。

| 模型 | 长度位置分 |
| --- | ---: |
| Jev 1.13.0 | −23.43 |
| Kev-4B | −23.94 |
| Kev-9B | −17.56 |
| StartLux-Decision-9B | −13.59 |
| Qwen3.5-9B | −15.58 |
| Llama-3.1-8B | −22.19 |
| Kev-0.8B | +1.76 |
| Intern-Decision-0.8B | +4.10 |

两类里都有偏短的选择结果，小模型的方向也不一致。上表只是观察点估计，
不能据此把模型家族分成两种“性格”；网页同时保留每模型的题目抽样区间。

## 2. 同一个模型，换任务后甚至会反向

例如 Kev-9B 在长度可区分的 CRUXEval 原题上，位置分为 **+8.01**（94 题）；
在 When2Call 上为 **−36.46**（128 题）。但这两套题的正确答案自身也有不同
的长度分布：分别为 +7.39 与 −14.06。因此不能把方向变化全归因于模型。

比较有价值的问题是：它是在识别正确语义，还是更偏向某一种常常写得短的
动作？When2Call 的候选包含不同工具决策，长度和动作含义未被独立控制。
这是后续实验应当拆开的两个因素。

## 3. 答错时偏短，值得追查，但还不能说它在“蒙”

在 Jev 答错的 31 道有效 When2Call 题中，所选答案的位置分为 **−50.54**；
同一批题如果从错误选项里随机挑一个，基线为 **−3.23**。这是一个值得做
扩写干预实验的信号。但“答错”不等于“模型自己无法判断”，短选项的语义
也可能造成这种现象。其他模型的错题不同，不能当成同一批难题直接横比。

## 4. 有些数据集根本不适合直接证明长度偏好

另外七项任务大多使用固定标签。一个模型若常选“未提及”，恰好该标签更长，
就会产生偏长的统计结果。把这种类别偏好包装成“喜欢详细描述”是不严谨的。
网页保留这些任务供检查，但不把它们作为默认主图。

“四选一且最短唯一”也单独列出；这不等于另外三个选项严格等长。
选项全部等长的题没有辨别力，二选一也无法判断“错误选项之间”的长度偏好。

## 尚未完成的关键验证

同一道题、同一个选项意思不变，只把描述扩写，再交换位置，看模型是否改选。
应分别扩写正确项和干扰项，先审查等义性、答案泄漏与输入截断。重复描述
还会改变强调程度，因此要称为“冗余扩写敏感性”，不能自动声称隔离了纯长度。
v1 没有报告这项干预已完成，也没有为此新增任何模型调用。
